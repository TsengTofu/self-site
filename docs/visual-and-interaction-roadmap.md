## 一、three.js 建模的可能性評估

### 路線 A:完整 3D 房間(Blender 建模 → glTF → React Three Fiber)
把整個房間用 low-poly + toon shader(卡通渲染)重建,材質用手繪貼圖保留插畫感。
- ✅ 終極擴充性:鏡頭自由移動、物件隨意增刪、動物 = 有骨架的 3D 模型、海 = 真的可以「走過去」
- ✅ 業界已有成熟範例(Bruno Simon 個人網站、三渲二 toon style)
- ❌ 成本最高:需要學/外包 Blender 建模,要重現這張插畫的筆觸最難(AI 圖 → 3D 資產無法自動轉換)
- ❌ 手機效能與載入(gltf + draco 壓縮可解,但要花功夫)
- 📦 技術組合:`three` + `@react-three/fiber` + `@react-three/drei`,toon shader 或 baked lighting
- ⏱ 粗估:數週級(對比其他路線的數天級)

### 路線 B:2.5D 圖層劇場(強烈推薦的甜蜜點)⭐
不建 3D 模型,而是把「這張插畫」拆成 8–12 層去背 PNG(天空海景/遠山/窗框/牆面/桌子/
桌上物/椅子/前景植物…),在 three.js(或純 CSS/GSAP)裡排成有深度的平面舞台。
- ✅ **100% 保留現在的風格**(素材就是原圖切出來的)
- ✅ 增減元素 = 增減一張圖層;動物 = 會動的 sprite 圖層(見第三節)
- ✅ 「海拉近」自然成立:鏡頭往窗戶推,海層放大,切換到海景互動模式
- ✅ 效能好、手機友善;GSAP 你已經在用
- ❌ 需要分層素材:用 AI 重生成單件素材(同 prompt 風格)或 Photoshop 生成填充拆圖
- 📦 技術:現有 stack 就夠(GSAP + 絕對定位圖層);要更絲滑再上 three.js 平面
- ⏱ 粗估:素材備齊後 2–3 天

### 路線 C:單圖深度視差(已試過,已否決)
上次的 three.js depth-map 方案 — 你不喜歡那個感覺,已移除,不再考慮。

### 結論
> 想要「空間感 + 擴充性」但保留這張圖的靈魂 → **路線 B**。
> 想要「真 3D 網站」作為長期作品 → 路線 A,但建議等 B 驗證玩法後再投資。

## 二、視覺風格的擴充路線(喜歡現在的風格,但要能長大)

核心矛盾:單張 AI 圖 = 風格滿分、擴充零分。解法是把「一張圖」變成「一套素材系統」:

### 選項 1:分層資產化(對應路線 B)⭐ 推薦首選
原圖當 master,逐步把會動/會變的部分摳出來獨立成層:
海景層、貓咪層、窗簾層、螢幕內容層…其餘維持整張底圖。
- 漸進式:今天摳一層就多一個可動元素,不用一次翻掉
- 增刪元素:請 AI 用同風格生成單件(戴帽子的貓、新的海報),去背後疊上去
- 風險:AI 補生成的單件與原圖的光影可能微妙不合 → 靠統一色調濾鏡收斂

### 選項 2:委託插畫師建立「素材庫版」
拿這張圖當 style guide,請插畫師重繪成分層 PSD(或 AI + 人工修)。
- 一次到位、風格完全可控、商用授權乾淨(AI 圖商用要留意生成平台條款)
- 成本:插畫委託行情約數千到上萬台幣/張(分層另計)

### 選項 3:向量重繪(SVG 版素材系統)
以現在的 SVG fallback 場景為基礎,把它的品質往這張插畫推(筆觸紋理、噪點、漸層)。
- 擴充性無限、檔案小、任何元素天生可動畫
- 但要承認:SVG 手繪感天花板存在,很難 100% 到位;適合當「風格 2.0」而不是複製品

### 選項 4:三渲二 3D(對應路線 A)
Blender + toon shader 統一美術,從此所有新元素都在同一套 pipeline 產出。
- 是「未來式」選項;等網站玩法穩定、確定要長期經營再上

### 關於你點名的三個需求,各選項的支援度

| 需求 | 分層資產化 | 插畫師素材庫 | SVG 重繪 | 三渲二 3D |
|---|---|---|---|---|
| 增/刪元素 | ◎(補一層) | ◎ | ◎ | ◎ |
| 活的動物 | ◎ sprite/Lottie | ◎ | ○ SVG 骨架動畫 | ◎ 骨架 |
| 海拉近+互動 | ◎ 海獨立成層 | ◎ | ○ | ◎ |
| 保留現在的味道 | ◎ | ◎(看畫師) | △ | △ |
| 成本 | 低 | 中 | 中 | 高 |

**建議路徑:選項 1 起步(先摳「海」和「一隻貓」兩層驗證),風格穩定後視需要升級選項 2 或 4。**

### 海景互動的具體想像(分層後)
- 點窗戶 → 鏡頭推進(GSAP zoom,同現在點電腦的機制)→ 進入「海景模式」
- 海景模式:帆船緩慢航行(位移動畫)、點海面 → 漣漪 + 海豚躍出、
  雲隨時間飄、時段系統直接對海景層換色(現有 phase 系統可沿用)
- 退出 = ESC / 點岸邊,鏡頭拉回房間

## 三、彩蛋與動態細節提案(躲貓貓、個人狀態…)

### 主打:躲貓貓的貓 🐈⭐
一隻同風格的小貓(sprite 幾格動畫就夠),每次載入隨機躲在一個地點
(桌下/黑膠櫃後/窗台花盆後/床底,只露耳朵或尾巴)。
- 找到點擊 → 貓跳出來伸懶腰 + toast「被你找到了!(3/7)」,localStorage 記錄找過的藏點
- 全部找齊 → 解鎖小獎勵(隱藏歌單?特別的 profile 卡?)
- 偶爾「不在家」— 跟在座狀態連動:主人離開時貓才出來睡在椅子上

### 個人狀態的延伸(現有右上角 badge 之上)
- **狀態訊息**:手機 lock screen / 螢幕上顯示你手動設的一句話(「衝刺 OneMeowDay 中」「聽 BND 循環第 47 次」),資料放 `data/status.ts` 或未來接 API
- **真實作息連動**:上線時段設定表(週間 9-18 上線),讓「離開」更像真的
- **Spotify/YouTube 正在聽**(未來):接 Spotify API 的 now-playing,顯示在 Marshall 音響旁

### 其他動態細節(小而美,任選)
1. **分頁標題彩蛋**:切到別的分頁 → title 變「(人不見了…)」;回來 →「歡迎回來 👋」
2. **深夜彩蛋**:00:00–05:00 造訪 → 螢幕變成唯一光源 + toast「這個時間…你也是夜貓子?」
3. **時鐘同步**:圖裡兩個螢幕的 10:30 換成即時時間(把螢幕摳成一層或直接 HTML 疊字)
4. **久置動態**:滑鼠 60 秒沒動 → 窗外飛過海鷗/貓探頭看你
5. **Konami code / 打字彩蛋**:輸入 `bnd` → WHY.. 海報發光 + 播放 BGM
6. **點擊計數彩蛋**:同一物件連點 10 下 → 各物件客製吐槽(手搖杯:「再點也不會續杯」)
7. **游標波紋**:點海面(分層後)產生漣漪;點室內產生小星星
8. **鬧鐘連動**:你的 use-alarm 實作完成後,鬧鐘響 = 場景震動 + 手機亮起,再點才停
9. **訪客足跡**:第 N 次來訪 toast「第 5 次見面了,要不要乾脆加個書籤?」(localStorage)
10. **海報輪播**:BND 回歸期(手動設定日期區間)海報自動換新專輯視覺

### 實作優先序建議(等你點頭再動工)
1. 分頁標題彩蛋 + 深夜彩蛋 + 點擊吐槽(半天,零素材需求)
2. 即時時鐘上螢幕(半天)
3. 躲貓貓(需要 1 隻貓 sprite 素材,1–2 天)
4. 海景分層 + 海互動(素材到位後 2–3 天)
